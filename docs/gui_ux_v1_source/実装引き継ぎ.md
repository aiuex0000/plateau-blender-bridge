## まず結論

現行Windows版Bridgeの機能は保持したまま、利用者の入口だけ作り直す。**初回は「かんたん画面」が既定**。EPSG/LOD/座標軸/CLI実行パス/ログ/手動OBJモード等は「詳細設定」に残す。別の変換実装・配布形式へ移行する必要はない。今回渡す `.html` はUXの動作試作であり、そのHTML自体をWindowsアプリに採用する指定ではない。現行Tkinterソースへ翻訳・組み込む想定。

## 具体的な実装範囲 — Phase 1

1. Windows現行ソース一式を保全し、コミット/パッチ済みnusamai版を特定する。既存EXE稼働中の `dist` への直接ビルドは禁止。新規ブランチまたは隔離作業フォルダで開始。
2. TkinterのGUIウィジェット構造を `place / size / save / summary / status / advanced` に再配置する。**同じバックエンド呼び出し**を維持する。
3. 起動直後は中心点指定、広さ400m、現行の実機成功既定値を使う。Googleマップを既定ブラウザで開くボタン (`webbrowser.open('https://www.google.com/maps')`) とコピー手順を表示。
4. 座標は `緯度, 経度` の順番。空欄、余分な数字、非数値、範囲外には日本語の改善案を出す。**緯度経度を無理に推測したり、逆順を黙って入れ替えない**。
5. 矩形・メッシュを別方式として残す。矩形は `西端経度, 南端緯度, 東端経度, 北端緯度` という既存内部順序へ明示的に変換する。中心点方式と数字の順番が異なることに注意。
6. 200m/400m/800mの広さ選択はUI候補。現行の既定400m・内部範囲上限50〜3000m・取得上限等との整合を確認。負荷・ダウンロード量は保証せず、現行 `preview` 等の実測見積りが利用可能なら任意で明示。
7. パス検出に成功したら「準備OK」と表示し、Blender/nusamaiの長い絶対パスは詳細画面へ移す。失敗した場合のみ「設定を確認」へ案内。
8. 生成前に、入力した座標/範囲、広さ、保存ファイル、取得対象（建物・地形・航空写真）を要約。既存ファイル上書き禁止と資源上限を維持。
9. 進行時は「データを探しています → 建物を準備しています → 地形と写真を準備しています → Blenderで保存・確認しています」という段階を表示。測れない進捗の％は作らない。
10. 完了した場合のみ「Blenderで街を開く」。失敗した場合はユーザー向け説明＋折りたたみ詳細ログ。キャンセル、取得確認、環境診断、自己診断、手動OBJモードは維持（詳細内等へ移動）。

## v0.10コードで確認できたGUI→エンジンの接続点（最新ソースでは要照合）

旧 `AutoGui.build_request()` は `AutoRequest(condition,epsg,output_blend,blender_executable,nusamai_executable,lod,photo_zoom,terrain_resolution,axis_override,clip_requested_area)` を生成し、`preview(req)` と `generate(req,log,cancel)` を呼び出す。ワーカー/queue/CancelToken、`last_result` からのBlender起動、自己診断 `run_smoke` を使う。

- 旧GUIの `bbox` は `condition='r:'+west,south,east,north`。
- `mesh` は `condition='m:'+code`。
- 中心点は実装・検証担当AIが実装しているため、**現在の中心点 condition 仕様を実装から確認**し、400m等を渡す。旧v0.10の `place='g:'+raw` を中心点と誤認して流用しない。
- 詳細設定の値は、初期v0.10の古い `min_lod`, zoom16 ではなく、**実装・検証担当AI版で成功した既定値**を読み込む。設定値のリセット事故に注意。

## 画面仕様の優先度

- P0: 文字とボタンの整理、中心点入力+マップ導線、広さ、保存先、かんたん/詳細切替、完了・失敗表示、既存機能への回帰防止。
- P1: 初回ガイドの開閉、取得サイズの初心者向け表示、クリップボード貼り付け補助、詳細ログの保存、150% DPIでの確認。
- P2: Googleマップの直接座標URL `@lat,lon` のローカル解析、短縮URL解決（リダイレクト先を検証しプライバシーに配慮する設計が必要）、住所検索、埋め込みマップ、ステップ型ウィザード。

## 完了試験

- ① 簡単画面のみに技術用語がほぼ現れない。② 位置入力/矩形/メッシュコードがバックエンドへ正しく渡る。③ 既存ファイル非上書き。④ キャッシュ利用/停止/失敗/再試行が正しく動く。⑤ 池田・新宿の成功済み小範囲で `.blend` 独立再読込＋画像検証が通る。⑥ 125%・150% DPI、小画面で主要ボタンに辿り着ける。⑦ キーボードのみの操作、ログとエラー内容のコピーができる。⑧ Pythonを導入していない利用者環境でもEXEを起動できる（後段配布試験）。

## セキュリティ・配布

- `PLATEAU Bridge` の処理結果はPLATEAU/国土地理院由来。Google Mapsは場所探しの導線であり、その地図画像を同梱しない。
- 地名→座標の自動変換は行わず、地名・施設名が分からなくても座標で使える設計を優先。
- 現行ソースはGitHubの `projects/plateau-blender-bridge/` などへ保全すると設計担当AIも今後直接確認できる。コミット/公開/外部共有は開発者の既存運用方針を確認し、無断で外部公開しない。
