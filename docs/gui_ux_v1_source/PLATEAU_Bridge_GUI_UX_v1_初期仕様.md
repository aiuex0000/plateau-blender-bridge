# PLATEAU → Blender Bridge 初心者向けGUI改善仕様 v1

作成日: 2026-10-27
対象: Windows版の現行Bridge（ルナによる実機修正版）。対象GUIのスクリーンショットから確認できた情報および悠の要件に基づく。ソースコードは未取得のため、実装済みとは扱わない。

## 0. ゴールと非ゴール

**ゴール**: PC・Blender未経験者が、説明書を読み込まなくても「好きな場所を指定 → 3Dの街を作る → Blenderで開く」まで進めること。授業のような技術習得ではなく「触ってみる・体感する」ための道具。

**維持するもの**: 現行の実データ取得、nusamaiローカルパッチ、地形・写真・建物、Blender独立再読込検証、ログ、詳細診断、手動OBJモード、矩形・メッシュコード・中心点指定、キャンセル、各種安全制限。既存変換エンジンは改変せずGUIと入力検証の薄い層から着手。

**非ゴール（初期リリース）**: Google Maps画像の再配布／埋め込み、汎用住所ジオコーディング、フル地図表示、全地域の完全保証、シミュレーションの自動生成。

## 1. 現GUI観察（スクリーンショット）

現状は「地域の指定方法（中心点／矩形／メッシュコード）」「中心 緯度,経度（一辺m）」「Blender本体」「nusamai CLI」「保存する .blend」「Blender/CLI再スキャン」「EPSG」「建物LOD」「航空写真ズーム」「地形のサンプル密度」「OBJ座標軸」「矩形範囲への切り出し」「取得対象の確認」「生成」「中止」「完成したファイルを開く」「手動OBJモード」「環境診断」「Blender自己診断」「進捗・実行ログ」が、ほぼ同じ視覚的重要度で表示されている。

現画面下部のログはBlender自己診断の成功を示している。これは実際の街の生成成功と混同しないよう、ステータスを別表示する。

## 2. 推奨情報設計

### 2.1 かんたんモード（初期表示）

タイトル: **好きな街を3Dにしよう**
補足: 「場所を選んでボタンを押すと、Blenderで開ける街を作れます」

**ステップ1：場所を選ぶ**
- 大きめの「Googleマップで場所を探す」ボタン：既定ブラウザでGoogleマップを開く。
- 説明（3行以内）：①地図で場所を右クリック ②緯度・経度の数字をクリックしてコピー ③下の欄に貼り付ける。
- 入力欄ラベル「場所の座標を貼り付ける」。入力例は `35.6896, 139.6917`。空欄は入力例と区別する。
- 緯度・経度の順番と国土地理院等の出典との関係を小さく補足。未対応のGoogleマップ短縮URLを「何でも貼り付け可」と表現しない。
- 「別の指定方法」から矩形とメッシュコードを表示可能にする（詳細モード限定ではなく初心者も必要時に選べる）。矩形では西・南・東・北を4つの別ラベル付き欄にするか、既存書式を丁寧に案内。

**ステップ2：広さを選ぶ**
- 200m四方「小さめ・まず試す」／400m四方「標準」／800m四方「広め・処理が重くなりやすい」。数値は暫定UI候補で、現行上限・実測負荷と照合して決定。任意指定は詳細モードへ。
- 面積・実際の収録モデルによって所要時間や取得量が変動することを明示。見積りは可能なら「目安」として表示し、確約しない。

**ステップ3：保存先を選ぶ**
- 「保存先」にはパス全体よりファイル名を優先表示。変更は「保存先を変更」ボタンからファイル保存ダイアログ。
- Blenderとnusamaiが自動検出できた場合、パスはメイン画面に表示しない。異常時のみ「設定を確認」を提示。

**生成前**
- まとめを1行で表示：「〇〇付近／400m四方／建物・地形・航空写真を含む街を生成」。地名は実際に地名解決した場合のみ使う。解決できない場合は座標を表示し、勝手に地名を推測しない。
- 主ボタンは画面幅に近い大きさの **「3Dの街を作る」**。キャンセルボタンは生成中のみ目立たせ、未開始時は無効。
- 操作前に既存ファイルを上書きしない、取得上限を超える場合は理由・対処を分かる言葉で示す。実際の取得が失敗することはあり、成功を保証しない。

**進行中と完了**
- ステータスは「データを探しています → 建物を準備しています → 地面と写真を準備しています → Blenderファイルを作成・確認しています」の段階式。未知の割合を捏造しない。割合が測れる処理のみ％表示。
- 生成中は二重実行できないよう主ボタン制御。中止時は再開・再試行への道筋を表示。
- 完了時に「作成できました」と出力先を表示し、メインCTAを **「Blenderで街を開く」** に切り替える。
- 自己診断成功と実データ生成成功を明確に分ける。
- 詳細ログは折りたたみの「詳しい処理内容を見る」に格納。ただし失敗時の原因と対処はメイン画面に必ず表示。

### 2.2 詳細設定（任意展開）

現行の次の設定を残す：Blenderパス、nusamaiパスと再検出、EPSG（AUTO）、建物LOD、航空写真ズーム、地形サンプル密度、OBJ座標軸、矩形クリップ、メッシュ指定、手動OBJモード、環境診断、Blender自己診断、ログの保存。初心者に露出させないだけで削除しない。

ユーザーが詳細設定を開かない限り、既存の実機検証で正常だった既定設定を変更しない。将来の「画質：標準／高画質」は対応するパラメータを実測検証してから追加する。

### 2.3 初回ガイド

最初は「かんたんモード」1画面＋段階表示を優先し、別系統のウィザードは作らない。初めて使う人向けの「最初から案内」導線は用意し、必要性が確認できたときに共通フォームを順に見せるウィザードを追加（別エンジンを作らない）。

## 3. 文字・ボタン・アクセシビリティ

- ボタンは役割でグルーピング。主CTAを1つにし、診断と手動モードは詳細へ移す。
- 日本語のラベルは「街の場所」「広さ」「保存先」「作成」など行動に直結する語を使う。
- 文字サイズ・押下領域はWindowsの125%、150%表示倍率でも確認。キーボードTab移動、フォーカス表示、ボタンの活性／非活性を点検。
- 成功・警告・エラーは色だけでなく文言とアイコンで区別する。
- 長いパスは途中を省略表示し、クリック等で全文を確認できるようにする。
- バージョン、出典・利用条件、ヘルプはメインCTAを押しのけない位置に置く。

## 4. Googleマップ連携に関する境界

### 第1段階（確実・単純）
- 「Googleマップを開く」ボタンと座標のコピー・貼付説明。
- `緯度, 経度`（任意で従来の一辺m）を入力検証。数値の区切り、空白、日本語読点、範囲外を丁寧に扱う。
- Googleマップの航空写真や地図画像をダウンロードしているように見せない。Bridgeの地形・写真取得元は国土地理院、建物はPLATEAU。

### 第2段階（単体テスト後）
- GoogleマップのURLのうち、緯度・経度がURLに明記されたサポート対象形式をローカル解析。`@lat,lon` と、共有形式の一部は検証後に追加可能。
- `maps.app.goo.gl`など短縮URLは単純な文字列解析では座標が得られないことがある。ネットワーク・リダイレクトの安全性、プライバシーを設計しないまま自動追跡しない。
- 地名・住所検索は別途ジオコーディングが必要。ライセンス・レート・利用者データを確認したうえで別件として扱う。

## 5. ルナ向け実装順と安全策

1. 現行Windowsソース／Git差分を保全し、バージョン・パッチ済みnusamaiを固定する。作業対象はGUI層。既存EXEに直接上書きビルドしない。
2. GUIのレイアウト・文言だけを変更。既存の自動生成リクエスト組み立てと安全制限はそのままにする。
3. Googleマップを開く導線、中心点入力の検証、簡単／詳細の切替を追加。
4. 入力エラー、生成前の確認、進捗、完了・失敗表示、詳細ログ折りたたみを実装。
5. GUIテスト（入力→内部AutoRequest相当へのマッピング、設定永続化、二重クリック防止、キャンセル、縮小画面）を追加。
6. `dist-next` にビルドし、既存の成功済み池田・新宿の再生成（小範囲・キャッシュ利用可）とBlender独立再読込検証。既存 `dist` は停止・退避後に入れ替える。
7. PythonなしのWindows PCまたは隔離環境で起動、初学者に説明なしで操作してもらう実地確認。詰まった箇所を記録してGUI・マニュアルの双方へ反映。

## 6. 完了基準（最低限）

- 既存の中心点・矩形・メッシュ指定、生成、キャンセル、ファイルを開く機能を失わない。
- 初心者の初期画面にはEPSG、LOD、座標軸、CLIフルパスを表示しない。
- Googleマップへ確実に移動でき、緯度・経度のコピー方法が画面上で分かる。
- 最小操作：場所貼り付け → 広さ選択 → 生成 → Blenderで開く。
- 失敗時はエラー番号だけでなく、ユーザー向け説明と「詳細ログ」を用意。
- 既存実機の検証用フローで、保存済み `.blend` の独立再読込とテクスチャ確認に回帰がない。
- 事業所の小画面・非高性能PC・Windowsの表示倍率でボタンが見切れない。
