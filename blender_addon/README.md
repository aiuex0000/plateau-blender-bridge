# PLATEAU Bridge（Blender アドオン版）

exe 版を、Blender の中で動く純Python のアドオンへ作り直している。経緯と段取りは `docs/handoff_2026-11-11_blender-addon.md`。

## 中身

| 場所 | 役割 |
|---|---|
| `plateau_bridge/` | 本体。段4（操作パネル）まで |
| `plateau_bridge/jprcs.py` | 平面直角座標系（EPSG:6669〜6687）の変換と系の選択。pyproj の代わり |
| `plateau_bridge/tiles.py` | 地理院タイルの取得と保存。bpy に依存しない |
| `plateau_bridge/terrain.py` | タイルの画素を Blender で読み、地形メッシュと写真テクスチャを作る。Pillow の代わり |
| `plateau_bridge/catalog.py` | PLATEAU のデータカタログ API から CityGML を探して取得する。exe 版の `catalog.py` の移植 |
| `plateau_bridge/citygml.py` | CityGML を逐次読みし、範囲に掛かる建物の面を取り出す。nusamai の代わり。bpy に依存しない |
| `plateau_bridge/buildings.py` | 読んだ面を numpy でまとめて平面直角座標へ変換し、メッシュにする |
| `plateau_bridge/textures.py` | CityGML が参照するテクスチャ画像の URL を解決し、並行して取得・保存する。exe 版の `appearance.py` の移植。bpy に依存しない |
| `plateau_bridge/atlas.py` | 数千枚のテクスチャ画像を、数枚の 4096x4096 の画像（アトラス）へ詰める |
| `plateau_bridge/place.py` | 利用者が入れた場所の文字（緯度経度、地図の URL、度分秒、範囲、メッシュコード）を読む。有名な場所の一覧。bpy に依存しない |
| `plateau_bridge/job.py` | 時間の掛かる通信と CityGML の読込みを裏のスレッドで進め、進み具合と取り消しを受け持つ |
| `plateau_bridge_trial/` | 段0の試作。会社PCで入るか・通信できるかを確かめる用 |
| `build_zip.py` | インストール用の zip を `dist/` へ作る |
| `tests/check_jprcs.py` | 座標変換を pyproj と、系の選択を既存の `plateau_blend/crs.py` と突き合わせる |
| `tests/check_place.py` | 場所の文字の読み方を確かめる。通信なし |
| `tests/check_textures.py` | 画像の URL 解決の拒否規則、取得と再利用、上限を、通信なし（偽の opener）で確かめる |

## 作り方と確かめ方

```
"C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" blender_addon/build_zip.py
.build-venv/Scripts/python.exe blender_addon/tests/check_jprcs.py
"C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" blender_addon/tests/check_textures.py
"C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" blender_addon/tests/check_place.py
```

zip は Blender の画面へドラッグ＆ドロップで入る。サイドバー（N）の「PLATEAU」タブから使う。

## 決めたこと

- シーンに座標系（`plateau_bridge_epsg`）と原点（`plateau_bridge_origin_xy`、平面直角座標の東・北 m）を残す。同じシーンへ後から取り込む物は、この原点からの相対位置に置く。建物（段2）もこれに合わせる。
- Blender の X は東、Y は北、Z は標高 m。
- 緯度経度の入力欄は文字列にする。Blender の数値欄は32bit精度で、経度が1m強ずれるため。
- 写真は画素を投影し直さない。タイルを1枚に並べ、地形の頂点ごとに UV を計算する。
- 標高タイルは海が無効値。標高を取れない地点は海として 0 m で通し、割合を結果に出す（2026-11-11 マスター判断）。範囲の全部で取れない時だけ止める。ここは既存版（0 m で埋めずに止める）と違う。
- 標高タイルの読み方（ズーム14、dem5a → 5b → 5c → dem の順、双一次補間、無効値の扱い）は既存の `plateau_blend/gsi.py` と同じ。

- 建物は範囲の線で切り、地形の四角にぴったり収める（既定。exe 版と同じ）。切り口には面を張って塞ぐ（既定。exe 版は塞がない）。建物の中が外と繋がらず、流体シミュレーションなどで隙間へ流れ込まない（2026-11-11 マスター判断）。切らずに丸ごと残すことも、塞がないことも設定で選べる。
- 切るのは Blender の二等分（`bmesh.ops.bisect_plane`）を4回、塞ぐのは `bmesh.ops.triangle_fill`。面が張られるのは、断面の輪郭が閉じている所だけ。
- 地形と建物には、最初から流体の障害物（Fluid の Effector、Collision）を付ける（既定。詳細設定の「水の障害物にする」で外せる。2026-11-12 マスター判断）。水の設定そのもの（Domain・Flow）はアドオンに入れず、マニュアルと配布データで扱う。アドオンは PLATEAU → Blender の変換に絞る。
- 建物ごとに、LOD の上限（既定 2）以下で一番詳しい形を使う。テクスチャの有無では選ばない。
- 多角形は n-gon のまま入れる。穴のある面だけ `mathutils` で三角形に割る。頂点は建物ごとに共有する。
- 区の境で同じ建物が複数のファイルに入っている時は、gml:id が同じ物を二度入れない。
- numpy は建物の頂点の変換とメッシュ化だけに使う（段0で、会社PCの Blender 同梱 numpy が読めると確認済み）。
- テクスチャは、面の輪（`gml:LinearRing`）の gml:id で UV と結び付ける。定義が建物より前にあっても後にあっても読めるよう、ファイルを読み終えてから結び付ける。
- 画像1枚ごとにマテリアルを作らない（新宿 1km 四方で5,161枚になる）。全画像を同じ倍率で縮めてアトラスへ詰め、マテリアルはアトラス1枚につき1つ。倍率は、枚数の上限（既定 4）に収まる一番大きい値を 2 の 1/4 乗刻みで選ぶ。
- 画像の保存名は短いハッシュにする。データセット内の相対pathのまま置くと、全長が Windows の260文字に届きうるため。
- アトラスは JPEG で保存してから .blend に埋め込む。
- パネルは exe 版の Web 画面の流れ（場所 → 広さ → 設定の確認 → 「3Dの街を作る」→ 進み具合と中止 → 「街ができました！」）に合わせる。保存先の質問は外す（Blender の中では利用者がそのまま保存できる）。Blender や nusamai の場所の質問も要らない。
- ボタンから押した時は、通信と CityGML の読込みを裏のスレッドで進め、画面を止めない。裏のスレッドは bpy.data に触らない。画像の読込みとメッシュ化だけ、終わった後に表で行う。画面なし（`-b`）で呼んだ時は終わるまで待つ。
- 範囲やメッシュコードで指定された時、建物は指定そのものの範囲で探す。メッシュは境界から約10cm 内側へ寄せる。そうしないと隣のメッシュのデータまで取りに行く。
- 取得済みのデータは「今回の設定をすべて見る」の中の「取得済みのデータを消す」で消せる。

## 確かめた結果（2026-11-11、Blender 5.2.3）

- 段0: 松井さんの会社PC（スマートアプリコントロール有効、Blender 5.2.2）で成功。ssl・_elementtree・_hashlib・numpy も読めた。
- 座標変換: 全19系で pyproj との差は最大 3.5e-8 m。系の選択は5,000地点で既存版と一致。
- 段1: 東京駅 1km 四方で既存版と比較。頂点の水平位置の差は最大 5e-7 m、標高の差は最大 0.5 mm。写真の色は位置を合わせた時の平均差が 5.7/255、5画素ずらすと 26/255。
- 段2: 新宿のメッシュ 53394525（92MB、1,600棟、LOD1 と LOD2 が混在、穴のある面4つ）を nusamai（max_lod、EPSG:6677）と比較。頂点の集合は一致（差 1 mm 以内、欠け・余りなし）、表面積の差は 0.016%。頂点数は nusamai の 471,984 に対し 86,305。
- 段2 の速さ: 新宿駅西口 1km 四方（CityGML 4 ファイル・400 MiB、1,608棟、14万面）で、取得 28 秒、読込みと形づくり 13.5 秒。取得済みなら 13.5 秒。
- 段3: 新宿の14棟（画像48枚）を、exe 版の流れ（切り出し → 画像取得 → nusamai textured_max_lod）の出力と、同じカメラ・陰影なしで描いて比較。3視点の画素の平均差は 0.2〜0.6/255、8画素ずらすと 2.2〜6.5/255。
- 段3 の速さ: 新宿駅西口 1km 四方（画像5,161枚・52 MiB）で、画像の取得 63 秒、読込みと形づくり 20 秒。アトラスは3枚、大きさは元の35%。.blend は 21 MB。
- 段4: 窓ありの Blender 5.2.3 をスクリプトで操作して確認。渋谷 200m（CityGML 3 ファイル・282 MiB の初回取得）の40秒間、0.25秒ごとのタイマーが157回まわり続けた（画面は止まらない）。進み具合の文は段階ごとに変わり、「中止する」は0.3秒で効いた。完了時に3Dビューがマテリアル表示になり、作った物全体へ視点が合う。
- 範囲の切り取り: 東京タワー 200m で exe 版の流れ（nusamai → `clip.crop_obj`）と比較。建物は同じ43棟、残った面の面積は exe 版 77,060.2 m2 に対し 77,053.3 m2（差 0.009%）。塞いだ時、切り口の線上に開いた辺は 0 本（塞がない時 136 本）。

## 未決

- CityGML 1ファイルの読込み中（数秒）と、最後の組み立て（新宿 1km 四方で十数秒）は中止が効かず、組み立ての間は画面が止まる。
- 取り込みの途中で別の .blend を開いた時の動きは試していない。
- 取得したデータは、消すまでアドオンの保存フォルダに残る（新宿 1km 四方で CityGML 400 MiB、画像 52 MiB）。自動では消さない。
- マスターの Blender 5.2.3（日本語表示）で、東京タワー 200m が動くことを確認済み。松井さんの手元ではまだ。
- 切り口を塞ぐと、建物どうしが接している所に、3枚以上の面が集まる辺が少し増える（東京タワー 200m で 8 本から 15 本）。
- テクスチャの上限は 画像6,000枚・合計300 MiB（exe 版は CityGML 1ファイルあたり1,000枚・120 MiB。アドオンは切り出さずに範囲全体で数えるため広げた）。
- 範囲の上限は exe 版と同じ（CityGML 24 ファイル・600 MiB まで）。変えるかはマスターと決める。
- 4.1 以前の Blender では試していない。
